# Расширенные проверки и меню

Это добровольно включаемое расширение. Старые четыре отчёта, команды, квоты, черновики и схема SQLite сохраняются. Расширение не даёт прав записи в панель и не включает отправку клиентам.

## Проверки Remnawave 3.4.5

Маршруты и поля сверяются тестами с закреплённым `@remnawave/backend-contract@3.4.5`. Это проверка контракта, не доказательство наличия прав или успешности запроса на конкретной рабочей панели.

| Проверка | GET-маршрут | Что выводится |
| --- | --- | --- |
| Общая статистика | `/api/system/stats` | Всего пользователей и онлайн |
| Пользователи | `/api/system/stats` | Всего, ACTIVE/DISABLED/LIMITED/EXPIRED |
| Онлайн | `/api/system/stats` | Сейчас, сутки, неделя, никогда не подключались |
| Состояние нод | `/api/nodes/` | Агрегаты по состоянию |
| Список нод | `/api/nodes/` | Номер в текущем снимке, состояние, онлайн; пять строк на страницу |
| Ресурсы | `/api/system/stats` | CPU, память, uptime, как сообщает панель |
| Трафик | `/api/system/stats/bandwidth` | Значения API для фиксированных периодов, без преобразования единиц |
| Процессы | `/api/system/health` | RSS, uptime и event-loop delay; первые пять процессов |
| Хосты | `/api/hosts/` | Всего, включены, отключены |
| Профили | `/api/config-profiles/` | Число профилей, без конфигураций |
| Внутренние сквады | `/api/internal-squads/` | Число групп |
| Внешние сквады | `/api/external-squads/` | Число групп |
| Версия | `/api/system/metadata` | Версия панели |
| Истекающие подписки | `/api/users/` | Прежний ограниченный отчёт за 1/3/7/14/30 дней |

Новые агрегаты доступны также через фиксированные инструменты локального `report-mcp.mjs`. Исходный автоматически генерируемый MCP-сервер и уже настроенный внешний трёхинструментный MCP этим не заменяются. Классификатор по-прежнему получает только вопрос, а не ответ панели; его прежняя JSON-схема не расширяется произвольными запросами.

Отказ API, отсутствующие поля и несогласованные счётчики означают недоступность, а не ноль. Включённый хост не равен проверенной сетевой доступности. Сумму подключений нод нельзя считать числом уникальных пользователей. Номера нод действуют только в текущем снимке и не являются постоянными ID. Периоды онлайн и трафика пересекаются. Пустой список runtime-метрик считается недоступностью: backend способен вернуть его при внутренней ошибке. Сам backend способен подставлять нулевой трафик при сбое своего запроса; бот не может достоверно распознать эту ситуацию по готовому ответу.

Формат трафика сохраняется из API: backend использует `prettyBytesUtil`, а не гарантированную строку целого числа байтов. Проверены числовые строки и ограниченные обозначения единиц; HTML и произвольные строки отклоняются. Семантика форматирования и fallback подтверждена в [официальном SystemService](https://github.com/remnawave/backend/blob/main/src/modules/system/system.service.ts) и [prettyBytesUtil](https://github.com/remnawave/backend/blob/main/src/common/utils/bytes/pretty-bytes.util.ts); это ссылки на текущий upstream, не зафиксированный серверный исходник версии 3.4.5.

## Текст без бюджета

- «Пришли статистику» → общая статистика.
- «Покажи количество пользователей» → пользователи по статусам.
- «Сколько юзеров онлайн?» → показатели онлайн.
- «Статистика нод» → состояние нод, не статистика пользователей.
- «Сколько пользователей на нодах?» → отдельные ноды, без суммирования уникальных пользователей.
- «У кого истекает подписка в ближайшую неделю?» → семь дней.
- После успешного отчёта о подписках «а за три дня?» меняет период. Контекст хранится только в памяти десять минут, не переживает перезапуск и не попадает в глобальный кеш.
- Неподдерживаемые даты, числа, фильтры, отрицания и смешанные предметы требуют уточнения кнопками, а не молча подменяются другим запросом или отправляются модели.

Это ограниченная грамматика, не универсальное понимание языка. Совсем неизвестный вопрос всё ещё может обратиться к ИИ, если он явно включён. Старые хеши кеша сохраняются; новые типы отчётов имеют отдельное пространство `intent-v2`, поэтому при откате старый код не прочитает неизвестное ему действие из старого пространства. Расход квоты не меняется.

## Меню без новых сообщений на каждое нажатие

Для своих меню используется [editMessageText](https://core.telegram.org/bots/api#editmessagetext). Подтверждение нажатия снимает индикатор ожидания. Каждая ревизия имеет новый случайный маркер, а редактирование разрешено только для ID сообщения, полученного от собственного успешного sendMessage в этом процессе. Сообщения бэкапов и уведомлений не принимаются за меню и не редактируются.

После перезапуска старое меню больше не действует: нужен `/menu`. Устаревшее нажатие не читает панель и не вызывает ИИ. При подтверждённом ответе Telegram «сообщение не найдено/нельзя редактировать» создаётся новое меню. При сетевой неопределённости отправка не повторяется и новое сообщение автоматически не дублируется. Это переключение содержимого, не анимация. Текстовая команда может создать новое сообщение; нажатия в актуальном меню редактируют его.

## Включение после сборки и CI

Из каталога приложения, после обновления на проверенный коммит:

```sh
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml -f compose.features.yaml config --quiet
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml -f compose.features.yaml build bot ai
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml -f compose.features.yaml up -d --no-build --no-deps ai bot
```

Без ИИ можно не добавлять `compose.ai.yaml`: локальное распознавание нового меню не зависит от классификатора или исправности SQLite. Сам учёт бюджета при повреждённом SQLite остаётся закрытым для новых модельных обращений. Нельзя запускать второй получатель того же Telegram-бота на другом VPS параллельно с первым.

После обновления: проверить `/menu`, переходы и возврат в том же сообщении, пользователей, онлайн, ноды, конфигурацию, подписки и контекст. Сравнить `/budget` до и после локальных фраз: он не должен измениться. Проверять новые read-only разделы по одному с интервалом пять секунд. При недоступности раздела не повышать права автоматически. Не публиковать отчёты с клиентами.

Вернуть прежнее меню можно без отката данных: пересоздать только bot теми же Compose-файлами, но без `compose.features.yaml`. Дополнительные отчёты и новые безопасные локальные алиасы остаются в коде. Для полного отката исходников выбрать ранее принятый коммит и пересобрать образы, не удаляя тома, кеш, квоту, offset и авторизацию. Снятие защитной паузы не является частью обновления.

## Следующие независимые этапы

Команды хоста для обслуживания, изменение настроек/токенов и полноценный проверенный бэкап/restore пока не входят в это расширение. Они должны быть отдельным этапом после серверной приёмки меню. Docker-сокет, произвольные команды хоста, операции записи в панель и рассылки через Telegram/MCP этим обновлением не предоставляются.
