# ИИ через подписку: отдельный добровольно включаемый модуль

## Границы

Базовый Compose по-прежнему запускает бота без внешнего ИИ. Новый `compose.ai.yaml` подключает отдельный контейнер `ai`; сам по себе файл не изменяет работающий контейнер. GitHub Actions не выполняет деплой и не использует авторизацию пользователя.

ИИ определяет только действие и период: `help`, `version`, `stats`, `nodes`, `expiring` и 1/3/7/14/30 дней. Затем бот сам вызывает фиксированный локальный MCP и оформляет свежие данные с кнопками. Списки клиентов, ответы панели, Telegram-токен и токен панели классификатору не передаются. Сам текст вопроса уходит провайдеру: не писать в нём персональные данные или секреты. Известные команды и хеш-кеш обходят ИИ.

Закреплён официальный npm-пакет `@openai/codex@0.162.1`, проверенный по публичным метаданным npm. Модель явно `gpt-6-luna`, reasoning `low`, без автоматического перехода на другую модель или платный API. Доступность именно этой модели для аккаунта проверяется отдельно после входа. Воркера нельзя считать проверенным на подписке только по успешному CI.

Файловая система контейнера только для чтения, UID 1000, удалены capabilities, нет опубликованных портов, Docker-сокета, host networking, файлов/секретов панели и Telegram. Лимиты: 0,5 CPU, 512 МиБ без дополнительного swap, 64 процесса. Бот и воркер общаются через Unix socket с правами 0600 в отдельном томе. Отдельные тома воркера содержат авторизацию и учёт. Том авторизации не подключён к боту. Сеть Compose допускает исходящие подключения и сама не ограничивает egress доменами провайдера. Лимиты runtime не ограничивают сборщик.

Вход — отдельный device-code flow на VPS, не перенос авторизации рабочего компьютера. Авторизация подписки сохраняется в приватном томе и доступна администратору Docker/хоста. Не копировать `auth.json`, не включать его в Git, резервные копии репозитория или сообщения. Код входа и снимок экрана со ссылкой/кодом не публиковать. Этот вход не использует административную сессию панели.

Наши SQLite-базы не сохраняют исходные вопросы и ответы панели. `ephemeral` и отключённая история уменьшают сохранение истории CLI, но не являются гарантией отсутствия любых служебных файлов, метаданных или журналов самого CLI. Весь том `CODEX_HOME` считать приватным, не только `auth.json`.

Образ явно устанавливает системный пакет `ca-certificates`. Вход, preflight и классификатор получают фиксированный `CODEX_CA_CERTIFICATE=/etc/ssl/certs/ca-certificates.crt`; проверка HTTPS-сертификатов не отключается. Slim-база и встроенные корневые сертификаты Node сами по себе не гарантируют наличие системного trust store для нативного CLI. CI проверяет чтение и разбор публичного CA bundle без сетевых обращений. Ошибка `error sending request` всё ещё может быть связана с DNS, маршрутом, временем или TLS; наличие bundle не доказывает доступность сервера входа с конкретного VPS. Не выводить содержимое файлов авторизации или полный login log при диагностике.

## Бюджет и аварийная остановка

- Бот резервирует максимум 10 попыток за московские сутки и одну в минуту, до обращения к воркеру. Воркер независимо резервирует максимум 10 запусков модели и один в минуту в своей SQLite. Это два предохранителя одного потока, не разрешение на 20 обращений.
- Ошибки, отмена и таймауты не возвращают попытки; повторов на уровне приложения нет. Перезапуск не сбрасывает SQLite. `/budget` показывает резервирования бота; сетевые сбои до воркера могут дать меньший фактический счётчик запусков модели.
- Только один запрос одновременно. Вопрос до 500 символов, stdout до 64 КиБ, ответ JSON до 256 символов, таймаут процесса 45 секунд с принудительной остановкой группы процессов. Новая пользовательская команда не вызывает модель сама по расписанию.
- Входящий контекст укорочен через `model_instructions_file`, история отключена, запуск ephemeral из пустого каталога. Отключены инструменты команд (`shell_tool`), code mode, плагины/apps/MCP, поиск, браузер/computer use, изображения, подагенты, цели, hooks и ряд вспомогательных функций. Закреплённая версия и отключённые функции проверяются до обслуживания запросов. Событие инструмента немедленно останавливает процесс и сохраняет паузу воркера.
- По завершении требуется корректный `usage`. Более 8000 входных или 1024 выходных токенов либо отсутствующие/невалидные метрики сохраняют паузу и запрещают новые обращения. Это **предохранитель после вызова**, не гарантия, что уже завершившийся вызов не превысит порог. Успешные журналы содержат только числовой usage, не вопрос/ответ модели.
- После паузы, неудачной авторизации или исчерпания лимита кнопки и известные локальные вопросы остаются доступны. Пять повторных неудачных стартов сохраняют локальную паузу без сетевых обращений. Не удалять тома/БД ради сброса счётчика.

Количество запусков, объём текста и таймаут не являются точным токеновым лимитом подписки: внутренний контекст, reasoning и сетевые повторы CLI могут влиять на расход. Отключены бесконечные сетевые повторы, но нет обещания одного HTTP-запроса на один запуск. Другие чаты аккаунта не учитываются. Не включать покупку дополнительных кредитов ради этого теста.

В CLI 0.162.1 пользовательское выключение служебного backend-флага `unified_exec` игнорируется, как указано в официальном справочнике. Запрет самих инструментов команд задаёт `shell_tool=false`; preflight обязательно проверяет именно этот запрет и остальные отключённые возможности. Значение backend-флага `true` не принимается за отдельное разрешение на команды. Регрессионный тест допускает этот backend при выключенном `shell_tool`, но отказывает, если `shell_tool` включён.

## Поэтапная установка

Только после разрешения оператора. Сначала обновить исходники до проверенного коммита, сохранив приватную `.env`, secrets и том бота. Не выполнять `down -v`, prune, перезапуск daemon или команды чужого проекта. Все команды ниже — из этого каталога приложения.

Собрать отдельный образ, не останавливая и не пересоздавая бота:

```sh
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml config --quiet
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml build ai
```

Разовый вход, без запуска получателя Telegram или запроса к модели:

```sh
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml run --rm --no-deps --entrypoint node ai /app/apps/telegram-admin/ai-login.mjs --device-auth
```

Ссылку открыть самостоятельно в браузере и ввести одноразовый код. Если вход по коду недоступен, проверить его включение в настройках безопасности аккаунта с подпиской/разрешениях workspace. Не копировать кеш авторизации как обход. Затем проверить только статус:

```sh
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml run --rm --no-deps --entrypoint node ai /app/apps/telegram-admin/ai-login.mjs --status
```

После успешного входа, отдельно проверяя каждый этап:

```sh
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml up -d --no-build --no-deps ai
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml ps -a
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml logs --tail=20 ai
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml build bot
docker compose -f compose.yaml -f compose.continuous.yaml -f compose.ai.yaml up -d --no-build --no-deps bot
```

Сначала `/budget` и известная фраза «статистика»: без ИИ. Затем одна новая переформулировка, например «Какова общая картина по пользователям сейчас?». Проверить ответ, одну попытку в `/budget` и числовой usage в безопасном журнале `ai`. Через пять секунд повторить ту же фразу: счётчик не увеличивается, MCP читает панель заново. Не проверять суточный предел десятью платными по подписке вызовами: это проверяют искусственные тесты. Telegram-бэкапы и исходящие уведомления панели должны продолжить работу; получатель их не скачивает и webhook не меняет.

## Отключение и восстановление

Остановить только `ai`, затем пересоздать только бота с базовым и continuous-файлом, без AI override: кнопки, локальные команды, кеш и бюджет сохранятся. Авторизация остаётся в отдельном томе; при необходимости отдельно вызвать `ai-login.mjs --logout` через тот же разовый контейнер. Это удаляет локальную авторизацию этого модуля, а не выходит из панели или рабочего компьютера.

Если сработал guard, сначала остановить `ai` и выяснить причину. Только после отдельного подтверждения оператора разовый контейнер с entrypoint `node` и аргументами `/app/apps/telegram-admin/ai-state-control.mjs --acknowledge-ai-pause` снимает паузу, не меняя квоту и авторизацию. Затем запустить только `ai`. Не запускать вторую копию получателя Telegram.
