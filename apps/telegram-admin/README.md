# Telegram-бот администратора: первый серверный этап

Отдельный контейнер для Remnawave 3.4.5. Кнопки вызывают только четыре GET-отчёта панели; ИИ и доставка клиентам отключены. Никаких обращений к панели по расписанию нет. Этот каталог не заменяет исходный MCP-сервер проекта.

## Возможности

- `/menu`, `/stats`, `/nodes`, `/version`, `/expiring` и inline-кнопки.
- Статистика, агрегированное состояние нод и версия панели.
- Активные подписки, истекающие за 1/3/7/14/30 дней: имя, ID панели, дата окончания в Москве, часы, трафик и признак привязанного Telegram. Только будущие активные подписки; до 1000 просмотренных пользователей, неполный отчёт помечается явно.
- По пять строк на страницу, обновление и черновики напоминаний. Подтверждение черновика не отправляет его клиенту. Все ответы разрешены только одному администратору в личном чате.
- Первый запуск: 15 минут с уведомлениями о запуске и остановке. Простые текстовые вопросы распознаются локально; новые вопросы через ИИ пока отключены.
- SQLite хранит только хеш вопроса и распознанную команду, но не ответы панели. Повторный отчёт каждый раз читает свежие данные через локальный MCP.
- `/budget` и кнопка «Лимит ИИ» показывают локальные попытки за московские сутки и число сохранённых команд. Подготовлен жёсткий предел 10 новых попыток в сутки и интервал не меньше минуты; ошибки учитываются до внешнего вызова. В этой сборке внешний классификатор ещё не подключён и попытки не расходуются.

## Безопасность и ограничения

Рекомендуется отдельный VPS без панели/нод. Ресурсные лимиты и изоляция уменьшают риск, но бот всё равно читает боевую панель и обрабатывает персональные данные. Нельзя считать широкие права токена безопасными только из-за названия «read only».

Нужны права чтения `/api/system/metadata`, `/api/system/stats`, `/api/nodes/`, `/api/users/`. Выбрать минимальные соответствующие категории в интерфейсе панели. Генерация ключей, биллинг, настройки, диагностические jobs и изменение подписок не нужны. Код не создаёт, не перевыпускает и не отзывает токены.

Compose использует отдельный проект и собственную стандартную сеть. Нет опубликованных портов, webhook, подключения к сетям панели/нод, Docker-сокета, privileged или host networking. Мостовая сеть допускает исходящие подключения и не является egress-фильтром. Процесс UID 1000, файловая система только для чтения, capabilities удалены. Лимиты работающего контейнера: 0,5 CPU, 256 МиБ без дополнительного swap, 64 процесса. Они не ограничивают Docker-сборщик; перед сборкой проверить свободные ресурсы.

Токены читаются из отдельных файлов, не из аргументов запуска. Файловые Compose secrets не шифруют файлы на VPS и не переназначают их владельца. Нужны защищённый хост, правильные права и возможность чтения под UID 1000. Эти файлы, `.env` и локальная конфигурация исключены из Git и Docker build context. Не передавать их через чат и не копировать весь каталог разработки на сервер.

Пароли, UUID, ссылки подписок, email/IP и Telegram ID клиентов не включаются в отчёты или журналы. Имена клиентов видны только разрешённому администратору. В памяти до 10 отчётов и 50 черновиков, срок жизни 10 минут. Том содержит только позицию очереди и локальную отметку цикла; это не долговечное хранилище черновиков. Журналы Docker ограничены размером и содержат фиксированные коды, а не сообщения/ответы панели.

Бот получает команды через getUpdates. Он не меняет webhook и не скачивает документы/резервные копии. Перед запуском остановить другой получатель команд этого бота; отсутствие webhook не доказывает отсутствие второго poller. При конфликте HTTP 409 цикл останавливается без повторного захвата. Положительный offset подтверждает просмотренные события обычным способом, без принудительной очистки очереди.

Позиция очереди сохраняется перед обработкой: после аварии отдельную команду может потребоваться отправить заново. Ответ с неопределённым результатом доставки не повторяется автоматически. Нет гарантии exactly-once. Healthcheck читает только локальную отметку цикла, не проверяет панель и не гарантирует работоспособность каждого отчёта.

## Первый запуск

Только после отдельного согласия на выбранном VPS. Проверить, что целевая папка и Compose-проект ещё не заняты. Не работать внутри существующего стека панели, ноды или другого приложения. Не обновлять ОС/Docker, не перезапускать daemon и не менять firewall для этого теста.

Скачать нужную тестовую ревизию репозитория в новую папку. Далее из корня репозитория:

```sh
bash apps/telegram-admin/configure.sh
```

Помощник требует интерактивный root-терминал на VPS. Спросит HTTPS-адрес панели без `/api`, имя бота без `@`, единственный Telegram ID администратора и два токена. Токены вводятся скрыто через терминал, не выводятся и не попадают в историю команд. Действующие файлы не перезаписываются. Помощник создаёт только приватные файлы этого приложения, ничего не запускает и не меняет настройки бота/панели.

Использовать существующий Telegram-токен, если он нужен панели для уведомлений/бэкапов; не перевыпускать его. Токен панели должен быть отдельным ограниченным. В Git публикуется только `.env.example` с искусственными значениями, никогда готовая `.env`.

Затем, по шагам, проверяя результат каждой команды:

```sh
cd apps/telegram-admin
docker compose config --quiet
docker compose build bot
docker compose up -d bot
docker compose logs --tail=50 bot
```

Обычный `docker compose config` раскрывает подставленные приватные настройки; не включать его вывод в публичные отчёты. Первый тест сам завершается через 15 минут, restart отключён. Уведомление об остановке может не дойти при сетевой ошибке — смотреть безопасный журнал.

Проверить меню, статистику, ноды, версию, подписки за 3 и 7 дней, страницы и черновик/подтверждение. Между чтениями выдерживать пять секунд. Убедиться, что посторонние пользователи и группы не получают данные. Не публиковать скриншоты списков клиентов. Никакой реальной отправки клиентам в этой версии нет.

## После приёмки

Только после отдельного подтверждения, в каталоге приложения:

```sh
docker compose -f compose.yaml -f compose.continuous.yaml up -d bot
```

Длительный режим снимает таймер, но не добавляет прав/ИИ/уведомлений. По отдельному решению оператора override использует `unless-stopped`: Docker запускает контейнер после своего перезапуска, если контейнер не был остановлен вручную. Это требует уже настроенного автозапуска Docker daemon. Проверка `systemctl is-enabled docker` только читает состояние; не включать/перезапускать daemon и чужие сервисы автоматически.

Конфликт получателей, webhook, неправильный бот или пять коротких неудачных стартов фиксируются в томе. При следующем старте процесс переходит в паузу без Telegram/панели/ИИ и без бесконечного повторного захвата получателя. Healthcheck показывает паузу как нездоровое состояние; Docker не перезапускает контейнер только из-за unhealthy. Администратор должен устранить причину и отдельно подтвердить снятие паузы, затем перезапустить только бота. Не очищать том ради сброса ошибки: там находятся позиция очереди и бюджет.

Для отката остановить только этот сервис:

```sh
docker compose stop bot
```

Не использовать `down -v`, `docker system prune`, команды чужих стеков или перезапуск Docker. Остановка получателя не меняет Telegram-токен и не должна отключать исходящие уведомления/бэкапы панели; это разделение проверить при приёмке.

## Проверки и следующий этап

```sh
npm ci --ignore-scripts
npm run build
npm run test:bot
```

Тесты работают только с искусственными данными. GitHub Actions проверяет тесты, синтаксис помощника, Compose и сборку/отказ запуска Docker-образа без подтверждения, без сетевого доступа и секретов. Запуск workflow не является деплоем и не подтверждает работу с боевой панелью. Базовый Docker-тег Node плавающий; после приёмки закрепить проверенный digest для повторяемости.

Локальный MCP-маршрут текста теперь реализован для известных команд и кеша. ИИ через подписку и защищённый вход на сервере — следующий этап. В этом образе нет Codex CLI, файлов авторизации ChatGPT или скрытого обращения к платному API. Внешний классификатор намеренно не включён; неизвестные вопросы предлагают использовать кнопки, не расходуя бюджет. Отказ будущего ИИ не должен блокировать кнопки. Не копировать авторизацию рабочего компьютера на VPS.

Подробности: [кеш и бюджет](AI-BUDGET.md). Суточные 10 попыток нашего приложения не равны точному лимиту токенов или остатка подписки. Таймаут, короткий вопрос и короткий JSON не гарантируют фиксированное число внутренних токенов Codex.

Источники: [сервисы Compose](https://docs.docker.com/reference/compose-file/services/), [файловые секреты Compose](https://docs.docker.com/compose/how-tos/use-secrets).
