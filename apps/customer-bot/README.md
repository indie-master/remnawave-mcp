# Отдельный клиентский Telegram-бот

Модуль предназначен для пользователей сервиса. Административный бот сохраняет управление панелью и очередь поддержки. Клиентский бот использует другой токен, контейнер, состояние и Unix-сокет. Он не получает токены панели, Codex-авторизацию, административный сокет и Docker socket.

Доступны кнопки своего аккаунта, поддержки, переписки и меню. Обычный текст добавляется в ту же историю, что и в кабинете. Локальные FAQ отвечают без модели; неизвестное обращение передаётся администратору. Последующие уточнения не создают повторных заглушек. Ответ администратора появляется в кабинете и доставляется именно клиентским ботом. Платёжные подтверждения, изменение пользователей и ИИ здесь не подключены.

## Подготовка и включение

По умолчанию модуль выключен. Сначала примите опубликованную ревизию обычными `botctl update FULL_SHA` и `botctl apply`. Далее работайте из `apps/telegram-admin` на VPS.

1. Создайте отдельного бота через [BotFather](https://core.telegram.org/bots/features#botfather). Не используйте токен административного бота. Действующий webhook или другой получатель этого нового бота должен отсутствовать; приложение не удаляет webhook автоматически.
2. Выполните `./botctl customer settings`. В приватном редакторе задайте:

```dotenv
CUSTOMER_BOT_ENABLED=true
CUSTOMER_BOT_USERNAME=example_customer_bot
```

Вместо примера укажите username нового бота без `@`. Затем `./botctl customer token` — двойной скрытый ввод его токена. Токен сохраняется в `apps/customer-bot/secrets/telegram-bot-token.txt`; существующий административный токен не читается и не копируется.

3. В `./botctl business settings` добавьте, сохранив остальные значения:

```dotenv
CUSTOMER_BOT_ENABLED=true
CUSTOMER_BOT_USERNAME=example_customer_bot
```

Username в двух настройках должен совпадать. Кабинет должен быть включён. Проверка подписки требует прежнего `PORTAL_PANEL_READ_ENABLED=true`; отсутствие чтения панели не мешает переписке. Цены, ИИ и поиск не нужно включать для этой приёмки.

4. Проверка, сборка и запуск одного комплекта:

```bash
./botctl business check &&
./botctl customer check &&
./botctl business build &&
./botctl customer build &&
./botctl business start &&
./botctl customer start &&
./botctl business status &&
./botctl customer status
```

Кабинет создаёт отдельный `customer-bridge`, затем запускается клиентский получатель. Новых входящих портов нет. Он проверяет `getMe`, отличие от административного username, отсутствие webhook и соответствие настройкам кабинета **до** `getUpdates`. Для получения обновлений используется [официальный Bot API](https://core.telegram.org/bots/api#getupdates); имя административного бота берётся из существующей базовой конфигурации и не редактируется в клиентском `.env`.

Если запуск не прошёл, используйте `./botctl customer logs`. Не очищайте состояние и не создавайте второй получатель. `customer stop` останавливает только новый модуль. Защитная пауза не снимается обычным обновлением или запуском: сначала нужно выяснить причину и отдельно согласовать контрольное восстановление. Токен, квоты и состояние административного бота не изменяются.

## Привязка и общая приёмка

Войдите в кабинет тестового пользователя. В разделе «Ваш Telegram» нажмите «Подключить Telegram», затем откройте созданную ссылку и нажмите «Запустить» в новом боте. Используется стандартная [ссылка Telegram с параметром start](https://core.telegram.org/bots/features#deep-linking). Код создаётся только в авторизованной сессии с CSRF-проверкой, действует пять минут и используется один раз. В SQLite хранится его хеш. Не пересылайте ссылку другому человеку.

Знание username, email или числового ID не привязывает аккаунт. Одна Telegram-учётная запись соответствует одному кабинету, а одна учётная запись кабинета — одному Telegram ID. Привязка локальная: Telegram-поле в Remnawave не меняется автоматически. Ссылки подписки и пароли боту не передаются. При необходимости отвяжите Telegram кнопкой кабинета; чтение и новые отложенные доставки прежнему получателю будут запрещены.

Проверьте одним сценарием:

1. В клиентском боте открыть «Мой аккаунт». Вернутся собственные балансы и, при доступном чтении, состояние и срок собственной подписки. Панель вызывается только по этой кнопке, не в фоне.
2. Открыть «Поддержка», отправить сообщение и несколько уточнений. Они появятся в той же переписке кабинета и в карточке клиента административного бота.
3. Администратор открывает карточку и пишет обычный ответ. Ответ должен появиться в кабинете и в личном чате **клиентского** бота. Дополнительное меню под каждым человеческим ответом не отправляется.
4. В кабинете нажать «Отвязать Telegram». Старый Telegram больше не должен читать аккаунт и переписку. Повторное подключение — только по новой ссылке кабинета.

Первый тест выполняется через прежний SSH-туннель кабинета; публичный домен для него не требуется. Самостоятельная регистрация, SMTP, публичный запуск сайта и подключение ИИ остаются отдельными расширениями.

## Доставка и перенос

Исходящие ответы сохраняются в собственной очереди вместе с сообщением, атомарно. У каждого запроса есть квитанция; один и тот же запрос не добавляет дубликат. Получатель закреплён за подтверждённой привязкой. При сетевой неопределённости Telegram не вызывается повторно автоматически: исходное сообщение остаётся в истории, которую клиент может открыть кнопкой «Переписка». После аварии запрос, начавший доставку, переходит в `uncertain` и не отправляется повторно. Это защита от двойных сообщений, а не обещание доставки при любом обрыве сети.

Неотправленные уведомления старше суток истекают. Завершённые уведомления хранятся до 30 дней, текст неопределённых уведомлений после этого очищается. Квитанции входящих сообщений ограничены последними 100 для Telegram-пользователя и 30 днями. История и привязки изолированы по аккаунтам.

`./botctl backup` включает бизнес-БД и состояние нового получателя: offset и защитную паузу. Все получатели источника остаются остановленными до ручного продолжения. На новой машине используйте ту же ревизию и тот же клиентский бот, восстановите доверенный снимок в пустое состояние, внесите настройки и токен отдельно. Одноразовые ссылки отзываются при восстановлении, незавершённые доставки не повторяются. Не запускайте два получателя одного бота одновременно.

Откат ядра останавливает дополнительный клиентский модуль и сохраняет его данные. Предыдущая версия может не понимать новые ключи `.env`: перед отдельным запуском старого кабинета отключите модуль и удалите новые ключи из его приватной конфигурации. Данные и финансовое состояние старым снимком не перезаписываются.
